막힌 장면

각 과제의 자동 검사 스크립트가 남긴 결과를 그대로 다시 보여 줍니다. 방어를 끄고 켜면서 같은 요청을 보내 보세요.

과제 7 · 플랜두씨 다이어리 2

GET /rest/v1/<자료 테이블>
Authorization: Bearer <로그아웃 전에 받은 토큰>
→ 200 OK
→ 내 자료가 그대로 조회됨

200 뚫렸습니다

JWT는 상태가 없어서, signOut()은 리프레시 토큰만 무효화합니다. 로그아웃한 뒤에도 토큰은 한동안 살아 있었습니다.

→ 200 OK
→ 0건

0건 막혔습니다

모든 RLS 정책에 session_is_active()를 추가했습니다. 같은 요청이 200이면서 내 자료 0건으로 바뀌었습니다.

과제 8 · 패스키 소개 페이지

패스키 삭제 요청을 재확인 왕복 중에 연타
→ 401
→ 남은 패스키 0개 (계정 소멸)

0개 뚫렸습니다

재확인 왕복 동안 화면이 살아 있어서 삭제 요청이 겹쳤고, 마지막 패스키까지 지워졌습니다.

→ 200
→ 남은 패스키 1개 유지

1개 막혔습니다

삭제하는 동안 목록을 잠그고, 연타를 재현하는 검사를 추가했습니다.

과제 8 · 패스키 소개 페이지

POST 계정 생성 challenge (로그아웃 상태) × 반복
→ 요청마다 새 계정 생성
→ 제한 없음

무한 뚫렸습니다

로그인하지 않았으면 무조건 새 계정을 만드는 구조였습니다.

→ 11번째 요청부터
→ 429 Too Many Requests

429 막혔습니다

IP 기준 속도 제한을 걸어, challenge를 발급하기 전에 먼저 막습니다.

방어전 · 공개 노출된 자료실

GET /api/notes
(로그인 없음)
→ 200 OK
→ 모든 메모가 목록에 보임

200 뚫렸습니다

시작 상태의 자료실은 비로그인으로도 전부 보였습니다.

→ 401
→ 단계별 점검 500/500

401 막혔습니다

로그인, 소유자 검사, 서버 단일 경로까지 5단계로 막았습니다. 공개 키로 직접 조회해도 401입니다.

요청을 보내면 응답이 여기에 나옵니다.
