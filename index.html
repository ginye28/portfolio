막힌 장면

각 과제의 자동 검사 스크립트가 남긴 결과를 그대로 다시 보여 줍니다. 같은 요청을 방어 전과 후에 보냈을 때의 응답이에요.

과제 7 · 플랜두씨 다이어리 2 — 로그아웃한 뒤, 같은 토큰으로 조회

GET /rest/v1/<자료 테이블>
Authorization: Bearer <로그아웃 전에 받은 토큰>
→ 200 OK
→ 내 자료가 그대로 조회됨

200 뚫렸습니다

JWT는 상태가 없어서, signOut()은 리프레시 토큰만 무효화합니다. 로그아웃한 뒤에도 토큰은 한동안 살아 있었습니다.

→ 200 OK
→ 0건

0건 막혔습니다

모든 RLS 정책에 session_is_active()를 추가했습니다. 같은 요청이 200이면서 내 자료 0건으로 바뀌었습니다.

과제 8 · 패스키 소개 페이지 — 패스키 삭제 중 연타

패스키 삭제 요청을 재확인 왕복 중에 연타
→ 401
→ 남은 패스키 0개 (계정 소멸)

0개 뚫렸습니다

재확인 왕복 동안 화면이 살아 있어서 삭제 요청이 겹쳤고, 마지막 패스키까지 지워졌습니다.

→ 200
→ 남은 패스키 1개 유지

1개 막혔습니다

삭제하는 동안 목록을 잠그고, 연타를 재현하는 검사를 추가했습니다.

과제 8 · 패스키 소개 페이지 — 로그아웃 상태로 계정 만들기 반복

POST 계정 생성 challenge (로그아웃 상태) × 반복
→ 요청마다 새 계정 생성
→ 제한 없음

무한 뚫렸습니다

로그인하지 않았으면 무조건 새 계정을 만드는 구조였습니다.

→ 11번째 요청부터
→ 429 Too Many Requests

429 막혔습니다

IP 기준 속도 제한을 걸어, challenge를 발급하기 전에 먼저 막습니다.

방어전 · 공개 노출된 자료실 — 로그인 없이 자료 목록 열기

GET /api/notes
(로그인 없음)
→ 200 OK
→ 모든 메모가 목록에 보임

200 뚫렸습니다

시작 상태의 자료실은 비로그인으로도 전부 보였습니다.

→ 401
→ 단계별 점검 500/500

401 막혔습니다

로그인, 소유자 검사, 서버 단일 경로까지 5단계로 막았습니다. 공개 키로 직접 조회해도 401입니다.

배포한 프로젝트

탭을 눌러 폴더를 열면 실제 배포 화면과 점검 결과가 나옵니다.

비로그인으로 전부 보이던 메모 서비스를 로그인, 소유자 검사, 서버 단일 경로까지 5단계로 방어했습니다. 단계별 점검 500/500, 되찾은 자료함 4/4.

배포 화면 열기 ↗

Supabase Auth와 RLS로 계정 간 자료를 격리하고, 로그아웃한 토큰의 재사용을 막았습니다. 로그인하지 않으면 자료 화면 자체가 열리지 않습니다.

배포 화면 열기 ↗

비밀번호 없는 WebAuthn 로그인을 단 소개 페이지입니다. 패스키 삭제 경합과 계정 무한 생성을 막고, 자동 검사 43개를 모두 통과시켰습니다.

배포 화면 열기 ↗

3분 안에 읽히는 공개 사이트와, 새 기록을 넣으면 다시 만들어 주는 재현 가능한 장치(refresh.mjs)입니다. 같은 입력이면 같은 결과가 나옴을 SHA-256으로 확인했습니다.

배포 화면 열기 ↗

실시간 기온을 보여 주되 장애 5종을 구분해 표시합니다. 장애 상황을 재현하는 fixture는 해시로 검증했습니다.

배포 화면 열기 ↗

클라이밍 완등과 실패를 난이도별로 기록하고 월별 성장 곡선을 봅니다. 영상은 내 브라우저(IndexedDB)에 먼저 저장하고, 공유를 켠 경우에만 올립니다. 저장소 쓰기 토큰은 서버에만 둡니다.

배포 화면 열기 ↗
