재현한 사례

각 과제의 자동 검사 스크립트가 남긴 결과를 그대로 다시 보여 줍니다. 방어를 끄고 켜면서 같은 요청을 보내 보세요.

로그아웃한 뒤에도 같은 토큰으로 자료가 조회됨

해결

플랜두씨 다이어리 2 · 인증과 격리

원인
JWT는 상태가 없어서, signOut()은 리프레시 토큰만 무효화합니다. 로그아웃한 뒤에도 토큰은 한동안 살아 있었습니다.
조치
모든 RLS 정책에 session_is_active()를 추가했습니다.
결과
같은 요청이 200이면서 내 자료 0건으로 바뀌었습니다.
GET /rest/v1/<자료 테이블>
Authorization: Bearer <로그아웃 전에 받은 토큰>

요청을 보내면 응답이 여기에 나옵니다.

→ 200 OK
→ 내 자료가 그대로 조회됨

200 뚫렸습니다

→ 200 OK
→ 0건

0건 막혔습니다

패스키를 지우는 중 연타하면 계정이 사라짐

해결

패스키 소개 페이지

원인
재확인 왕복 동안 화면이 살아 있어서 삭제 요청이 겹쳤고, 마지막 패스키까지 지워졌습니다.
조치
삭제하는 동안 목록을 잠그고, 연타를 재현하는 검사를 추가했습니다.
결과
401·0개에서 200·1개 유지로 바뀌었습니다.
패스키 삭제 요청을 재확인 왕복 중에 연타

요청을 보내면 응답이 여기에 나옵니다.

→ 401
→ 남은 패스키 0개 (계정 소멸)

0개 뚫렸습니다

→ 200
→ 남은 패스키 1개 유지

1개 막혔습니다

로그아웃 상태에서 계정을 무한히 만들 수 있음

해결

패스키 소개 페이지

원인
로그인하지 않았으면 무조건 새 계정을 만드는 구조였습니다.

결과

POST 계정 생성 challenge (로그아웃 상태) × 반복

무한 뚫렸습니다

해결

소개

로그인과 권한을 직접 짜 보고, 스스로 뚫어 보고, 막혔다는 증거가 나올 때까지 고칩니다.

게임과 제작 도구, 정보판을 만들다 인증(Supabase Auth·RLS)과 패스키(WebAuthn)로 넘어왔고, 패스키 보안을 직접 측정한 논문까지 썼습니다. 이어진 방어전 실습에서는 공개 노출된 자료실을 5단계로 지켜 500/500점을 받았습니다. 4인 팀 프로젝트 NEXUS WORK에서는 조장으로서 자동화와 공격 시험을 맡았습니다.
